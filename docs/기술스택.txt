================================================================
 배포 방법 — 두 가지 중 편한 쪽으로
================================================================

 화면과 서버가 한 프로그램에 들어 있어, 어느 방법이든
 **열어야 하는 포트는 8000 하나뿐**입니다. 웹서버(Apache/Nginx)를
 따로 두지 않아도 됩니다.


┌──────────────────────────────────────────────────────────────┐
│ 방법 A. Docker 를 쓰는 경우 (권장)                            │
└──────────────────────────────────────────────────────────────┘

  준비물: Docker, Docker Compose

    1) cp .env.example .env
    2) python scripts/set_password.py        (로그인 비밀번호)
    3) .env 에서 아래를 바꿉니다
         SECRET_KEY          아무 긴 문자열
         POSTGRES_PASSWORD   DB 비밀번호
         COOKIE_SECURE       https 면 true
    4) docker compose up -d --build
    5) http://서버주소:8000 접속

  PostgreSQL 도 함께 뜨므로 따로 설치하지 않아도 됩니다.


┌──────────────────────────────────────────────────────────────┐
│ 방법 B. Docker 없이 서버에 직접 올리는 경우                    │
└──────────────────────────────────────────────────────────────┘

  준비물: Python 3.12 이상, PostgreSQL, Node 20 이상(빌드용 1회)

  ─ 1단계. 화면 만들기 (한 번만)

      cd frontend
      npm ci
      npm run build            → frontend/dist/ 생성
      cd ..

    ※ Node 는 여기서만 씁니다. 이후 상시로 돌지 않습니다.
    ※ 서버에 Node 를 설치하기 어려우면, 다른 PC 에서 빌드한
       frontend/dist/ 폴더만 서버로 복사해도 됩니다.

  ─ 2단계. 파이썬 라이브러리 설치

      python -m venv .venv
      .venv/bin/pip install -r backend/requirements.txt

  ─ 3단계. 데이터베이스 준비

      PostgreSQL 에 데이터베이스와 계정을 하나 만듭니다.

        CREATE DATABASE bizdash;
        CREATE USER bizdash WITH PASSWORD '정한비밀번호';
        GRANT ALL PRIVILEGES ON DATABASE bizdash TO bizdash;

  ─ 4단계. 설정

      cp .env.example .env
      .venv/bin/python scripts/set_password.py

      .env 를 열어 아래를 채웁니다.

        DATABASE_URL=postgresql+psycopg://bizdash:정한비밀번호@localhost:5432/bizdash
        SECRET_KEY=아무_긴_문자열
        COOKIE_SECURE=true            (https 인 경우)

      SECRET_KEY 만드는 법:
        .venv/bin/python -c "import secrets;print(secrets.token_urlsafe(48))"

  ─ 5단계. 실행

      cd backend
      ../.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000

      표는 처음 시작할 때 자동으로 만들어집니다.
      http://서버주소:8000 으로 접속됩니다.

  ─ 6단계. 서비스로 등록 (재부팅 후 자동 실행)

      /etc/systemd/system/bizdash.service 를 아래 내용으로 만듭니다.
      (경로와 사용자 이름은 실제 환경에 맞게 고쳐 주세요)

        [Unit]
        Description=사업관리 대시보드
        After=network.target postgresql.service

        [Service]
        User=bizdash
        WorkingDirectory=/opt/bizdash/backend
        EnvironmentFile=/opt/bizdash/.env
        ExecStart=/opt/bizdash/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
        Restart=always

        [Install]
        WantedBy=multi-user.target

      등록:
        systemctl daemon-reload
        systemctl enable --now bizdash
        systemctl status bizdash


┌──────────────────────────────────────────────────────────────┐
│ 공통 — 첫 실행 후                                             │
└──────────────────────────────────────────────────────────────┘

  1) 로그인
  2) [사업 현황 (공고)] → [지금 수집]   → 공고 300건 이상 들어옵니다
  3) [신규 사업 등록] 으로 실제 사업 등록

  ※ https 로 서비스하려면 앞단에 Nginx 등을 두고
     8000 포트로 넘겨 주시면 됩니다.


================================================================
 전산실에 확인 요청드립니다
================================================================

  1. 서버에서 외부 인터넷으로 나갈 수 있습니까?
     ★ 가장 중요합니다.
       공고 수집이 이 서비스의 핵심 기능인데,
       막혀 있으면 아예 동작하지 않습니다.
       필요하면 위 4개 도메인만 열어 주셔도 됩니다.

  2. 고정 IP 가 있습니까?
     기관 사이트가 IP 등록을 요구하는 경우에 대비해 여쭙습니다.
     현재는 인증키 없이 접근되고 있습니다.

  3. https 인증서를 붙일 수 있습니까?
     비밀번호를 주고받으므로 https 를 권장드립니다.


================================================================
 참고 사항
================================================================

  · 이 서비스는 병원 내부 자료를 외부로 보내지 않습니다.
    외부와의 통신은 위 4개 기관 사이트에서 '읽어오는' 것뿐입니다.

  · 개발 환경에서는 SQLite 로 검증했습니다.
    'Docker 없이 직접 실행'(방법 B)은 실제로 띄워서 화면·로그인·공고
    조회까지 확인했습니다. 다만 그때도 데이터베이스는 SQLite 였습니다.

    PostgreSQL 연결과 Docker 구성은 서버에서 처음 실행하게 되므로,
    첫 기동 시 함께 확인해 주시면 감사하겠습니다.

  · 자동 테스트 63건이 포함되어 있습니다.
      cd backend && python -m pytest
