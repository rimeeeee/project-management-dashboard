# 계획 진척률의 시간대 — 확인 부탁드립니다

## 무슨 일인가

프로토타입은 계획 진척률을 이렇게 계산합니다.

```js
const s = new Date(p.start), e = new Date(p.end), n = new Date();
return Math.round(clamp((n - s) / (e - s), 0, 1) * 100);
```

여기서 `new Date("2026-06-01")` 은 자바스크립트에서 **UTC 자정**으로 읽힙니다.
한국시간으로는 6월 1일 **오전 9시**입니다. 즉 프로토타입은 사업이 시작일
오전 9시에 시작한 것으로 치고 있습니다. 의도한 것이라기보다 자바스크립트의
날짜 해석 방식 때문에 그렇게 된 것으로 보입니다.

옮긴 쪽은 한국시간 자정을 기준으로 합니다.

## 얼마나 다른가

`scripts/verify/run.py` 로 사업 2건 × 600일을 대조한 결과입니다.

| | |
|---|---|
| 다른 날 | 1,200건 중 **72건 (6.0%)** |
| 차이 크기 | **항상 정확히 1%p** (이식본이 1 큼) |

## 왜 신경 써야 하는가

상태 배지가 계획 대비 −5%p / −15%p 를 경계로 갈립니다.
계획 진척률이 1 크면 계획 대비가 1 작아지므로, 경계에 딱 걸친 사업은
어떤 날 '정상' 대신 '점검 필요'로 보일 수 있습니다.

지금 들어 있는 사업 2건은 경계에서 멀어서(+14%p, −26%p) 영향이 없습니다.

## 어떻게 할지

지금은 **한국시간 기준**으로 두었습니다. 이유는 두 가지입니다.

1. 사업이 시작일 오전 9시에 시작한다고 볼 근거가 없습니다.
2. 공고 마감 판정(`접수중`/`마감`)도 같은 '오늘'을 쓰는데, 그쪽은 반드시
   한국시간이어야 합니다. 두 기준이 서로 다르면 나중에 더 헷갈립니다.

**프로토타입과 완전히 똑같이 맞추길 원하시면** `backend/app/core/calc.py` 의
`calc_planned()` 한 함수만 UTC 자정 기준으로 바꾸면 됩니다. 말씀해 주세요.
