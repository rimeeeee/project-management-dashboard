================================================================
 사업관리 대시보드 — 설치 방법
================================================================

 이 폴더를 처음 받으신 분을 위한 안내입니다.
 순서대로 따라 하시면 됩니다.

 ※ 명령은 Windows 기준입니다. macOS · Linux 에서는
   .venv\Scripts\python.exe  →  .venv/bin/python
   copy  →  cp,   python  →  python3   으로 바꿔 읽으세요.

  설치되어 있는지 확인:

      python --version
      git --version


┌──────────────────────────────────────────────────────────────┐
│ 설치 (5단계, 10분이면 됩니다)                                 │
└──────────────────────────────────────────────────────────────┘


─── 1단계.  화면 (할 일 없습니다) ──────────────────────────────

  만들어진 화면이 frontend/dist 에 이미 들어 있습니다.
  서버에서 따로 만들지 않습니다.

  화면을 고치는 것은 개발 PC 에서만 합니다. 고친 뒤 결과물까지
  함께 올리므로, 서버는 받아서 쓰기만 하면 됩니다.
  자세한 것은 아래 '고친 뒤 서버에 반영하기' 를 보세요.


─── 2단계.  파이썬 준비 ────────────────────────────────────────

    python -m venv .venv
    .venv\Scripts\pip install -r requirements.txt


─── 3단계.  설정 파일 만들기 ───────────────────────────────────

    copy .env.example .env
    .venv\Scripts\python.exe scripts\set_password.py

  set_password.py 를 돌리면 로그인 비밀번호를 정할 수 있습니다.
  입력한 비밀번호는 암호화되어 .env 에 저장되고, 원문은 남지 않습니다.

  그다음 .env 파일을 열어 SECRET_KEY 를 바꿔 주세요.
  (로그인 쿠키를 암호화하는 값입니다. 기본값 그대로 두면 위험합니다)

  만드는 법:

      .venv\Scripts\python.exe -c "import secrets;print(secrets.token_urlsafe(48))"

  나온 값을 .env 의 SECRET_KEY= 뒤에 붙여넣습니다.


─── 4단계.  데이터베이스 (PostgreSQL) ──────────────────────────

  ※ 개발 PC 에서 시험만 할 때는 이 단계를 건너뛰세요.
    .env 를 그대로 두면 SQLite 파일로 돌아갑니다.

  1) PostgreSQL 16 을 설치합니다. 설치본이 Windows 서비스로
     자동 등록되므로 재부팅 후에도 알아서 켜집니다.

  2) 이 프로그램이 쓸 계정과 데이터베이스를 만듭니다.

     아래 psql·pg_dump 명령은 PostgreSQL 의 bin 폴더에 있습니다.
     경로째 쓰거나(예: "C:\Program Files\PostgreSQL\16\bin\psql.exe"),
     그 폴더를 PATH 에 넣어 두면 이름만으로 쓸 수 있습니다.
     pgAdmin 을 쓰면 명령 없이 화면에서 만들 수도 있습니다.

         CREATE USER bizdash WITH PASSWORD '정한비밀번호';
         CREATE DATABASE bizdash OWNER bizdash;

  3) .env 의 DATABASE_URL 을 아래처럼 바꿉니다.

         DATABASE_URL=postgresql+psycopg://bizdash:정한비밀번호@localhost:5432/bizdash

  4) 바깥에서 데이터베이스에 직접 붙지 못하게 막아 둡니다.

     설치 직후에는 listen_addresses 가 '*' 라서 5432 포트가
     네트워크 쪽으로 열려 있습니다. 확인해 보세요.

         netstat -ano | findstr ":5432"

     0.0.0.0:5432 로 나오면 열려 있는 것입니다.
     postgresql.conf 를 열어 아래처럼 고치고 서비스를 다시 시작합니다.
     (C:\Program Files\PostgreSQL\16\data\postgresql.conf)

         listen_addresses = 'localhost'

     관리자 명령 창에서:

         net stop postgresql-x64-16
         net start postgresql-x64-16

     ※ pg_hba.conf 가 기본으로 127.0.0.1 만 허용하므로 이대로 두어도
       바깥에서 붙지는 못합니다. 그래도 포트를 아예 열어 두지 않는
       편이 안전합니다.

  표(테이블)는 처음 실행할 때 자동으로 만들어집니다.

  백업은 하루 한 번 pg_dump 로 받아 두세요.

         pg_dump -U bizdash -Fc bizdash > bizdash_2026-08-31.dump

  ※ 받아 두는 것보다 '되돌려 보는 것' 이 중요합니다.
    처음 한 번은 아래처럼 다른 데이터베이스에 복구해 보고
    자료가 살아나는지 확인해 두세요. 그래야 진짜 백업입니다.

    복구용 데이터베이스를 만듭니다. bizdash 계정에는 이 권한이
    없으므로 postgres 로 만듭니다.

         psql -U postgres -c "CREATE DATABASE bizdash_restore OWNER bizdash"

    받아 둔 파일을 그 데이터베이스에 되돌립니다.

         pg_restore -U bizdash -d bizdash_restore bizdash_2026-08-31.dump

    자료가 살아났는지 세어 봅니다.

         psql -U bizdash -d bizdash_restore -c "SELECT count(*) FROM announcements"

    확인이 끝나면 연습용 데이터베이스는 지웁니다.

         psql -U postgres -c "DROP DATABASE bizdash_restore"


─── 5단계.  실행 ───────────────────────────────────────────────

    $env:PYTHONUTF8 = "1"
    cd backend
    ..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000

  ※ 위는 PowerShell 기준입니다. 명령 프롬프트(cmd)에서는
    첫 줄을  set PYTHONUTF8=1  로 씁니다.
    이 값을 빼면 로그의 한글이 깨져 읽을 수 없습니다.
    서비스로 등록할 때도 같은 값이 필요합니다(아래 Windows 절 참고).

  ※ 여기서는 8000 번으로 잠깐 띄워 확인만 합니다. 운영 서버는 80 번으로
    서비스 등록되어 있습니다(아래 Windows 절). 어느 포트로 보이든 같은 앱입니다.

  브라우저에서 아래 주소로 들어갑니다.

      http://localhost:8000              (같은 PC 에서)
      http://서버주소:8000                (다른 PC 에서)

  3단계에서 정한 비밀번호로 로그인하면 됩니다.

└──────────────────────────────────────────────────────────────┘

  위 5단계는 창을 닫으면 멈춥니다.
  재부팅 후에도 자동으로 켜지게 하려면 서비스로 등록합니다.


  1) .env 운영값 확인

     · APP_PASSWORD_HASH   3단계에서 정한 값이 들어 있어야 합니다
     · SECRET_KEY          기본값이면 반드시 바꿉니다
     · CORS_ORIGINS        비웁니다 (한 서버가 화면까지 내보내므로 불필요)
     · COOKIE_SECURE       http 로 쓸 것이면 false 그대로 둡니다
     · ROLE                적지 않습니다 (기본값 all — 화면과 API 를 함께)
                           프론트·백엔드를 다른 포트로 나눌 때만 씁니다.
                           아래 '다른 포트로 나누려면' 절을 보세요.


  2) 먼저 확인할 것 두 가지

     · 서버 PC 의 IP 가 고정인지 확인하세요.
       자동 할당(DHCP)이면 재부팅할 때 주소가 바뀌어서
       쓰는 사람들의 즐겨찾기가 한꺼번에 깨집니다.

     · 쓰려는 포트가 비어 있는지 확인합니다.
       지금 운영 서버는 80 번을 씁니다. 비어 있는지 확인하세요.

           netstat -ano | findstr ":80 "

       무언가 나오면 다른 프로그램이 쓰고 있는 것이니 그 포트는 피합니다.
       바꿀 때는 1024~49151 사이에서 고르세요. 49152 번부터는 Windows 가
       임시 포트로 쓰고, 6000·6665 같은 번호는 브라우저가 막습니다.

       ※ 80 은 http 의 기본 포트입니다. 그래서 주소에 포트를 붙이지 않아도
         (http://10.20.150.128) 붙인 것과(http://10.20.150.128:80) 똑같이
         열립니다. 브라우저가 :80 을 알아서 붙이기 때문이고, 포트를 숨기는
         설정이 있는 것이 아닙니다. 다른 포트로 바꾸면 주소에 꼭 써야 합니다.

       ※ 이 서버에 다른 프로그램을 함께 올릴 때는 80 을 피하세요.
         이미 이 앱이 쓰고 있습니다. 어느 포트가 쓰이고 있는지 봅니다.

             Get-NetTCPConnection -State Listen |
               Select-Object LocalAddress, LocalPort, OwningProcess |
               Sort-Object LocalPort


  3) WinSW 로 서비스 등록

     WinSW 는 아무 프로그램이나 Windows 서비스로 만들어 주는 도구입니다.
     github.com/winsw/winsw 에서 받습니다.

     받은 파일을 bizdash-service.exe 로 이름을 바꿔 설치 폴더에 두고,
     같은 폴더에 bizdash-service.xml 을 아래 내용으로 만듭니다.
     (경로와 포트는 실제 환경에 맞게 고쳐 주세요)

         <service>
           <id>bizdash</id>
           <name>사업관리 대시보드</name>
           <description>사업 진척 · 예산 관리 대시보드</description>

           <executable>C:\bizdash\app\.venv\Scripts\python.exe</executable>
           <arguments>-m uvicorn app.main:app --host 0.0.0.0 --port 80</arguments>
           <workingdirectory>C:\bizdash\app\backend</workingdirectory>

           <!-- 이것이 없으면 한글 로그를 만나는 순간 서버가 멈춥니다 -->
           <env name="PYTHONUTF8" value="1"/>

           <onfailure action="restart" delay="5 sec"/>
           <log mode="roll-by-size"/>
         </service>

     관리자 명령 창에서 등록하고 시작합니다.

         bizdash-service.exe install
         bizdash-service.exe start

     상태 확인 · 중지 · 등록 해제:

         bizdash-service.exe status
         bizdash-service.exe stop
         bizdash-service.exe uninstall

     ※ uninstall 은 반드시 stop 다음에 하세요. 멈추지 않고 지우면
       앱이 그대로 떠서 포트를 잡고 있어, 다음에 다시 설치할 때
       포트 충돌로 막힙니다. 이럴 때는 작업 관리자에서 python 을
       끝내거나  Get-NetTCPConnection -LocalPort 80 -State Listen 으로
       찾아 종료합니다.

     로그는 같은 폴더에 bizdash-service.out.log 로 쌓입니다.


  4) 방화벽 열기

     이 작업을 하지 않으면 서버 PC 에서만 화면이 보이고
     다른 PC 에서는 접속되지 않습니다.
     Windows 방화벽이 들어오는 연결을 기본으로 막기 때문입니다.

     관리자 PowerShell 에서 (대역과 포트는 실제 환경에 맞게):

         New-NetFirewallRule -DisplayName "사업관리 대시보드" `
           -Direction Inbound -Protocol TCP -LocalPort 80 `
           -Action Allow -RemoteAddress 10.20.150.0/23

     마지막 -RemoteAddress 가 '사내에서만 접속' 을 만드는 부분입니다.
     이 값을 빼면 어디서나 접속할 수 있게 열립니다.


  5) 접속 확인

     다른 PC 의 브라우저에서 서버 주소를 넣어 봅니다.

         http://10.20.150.128

     80 번이라 주소에 포트를 붙이지 않습니다. http://10.20.150.128:80 으로
     써도 똑같이 열립니다 — 브라우저가 :80 을 기본으로 붙이기 때문입니다.

     공고 수집은 서버가 대신 합니다. 쓰는 사람 PC 는 인터넷이
     안 되어도 되고, 서버 PC 만 아래 4곳에 나갈 수 있으면 됩니다.


  6) 백업 자동화

     PostgreSQL 은 파일 복사로 백업되지 않습니다. pg_dump 를 씁니다.
     자동으로 돌게 하려면 두 가지가 필요합니다.

     (가) 비밀번호를 파일에 저장 — 안 하면 스케줄러에서 멈춥니다

       자동 실행 때는 비밀번호를 물어볼 사람이 없습니다. pg_dump 가
       비밀번호를 기다리다 그대로 멈춰 백업이 안 됩니다. bizdash 계정의
       비밀번호를 pgpass 파일에 미리 넣어 둡니다.

       메모장으로 아래 파일을 만듭니다. (한 줄, 폴더가 없으면 만드세요)

           %APPDATA%\postgresql\pgpass.conf

       내용 (형식: 호스트:포트:DB:계정:비밀번호):

           localhost:5432:bizdash:bizdash:정한비밀번호

     (나) backup.bat 을 만들고 작업 스케줄러에 매일 등록

       아래를 C:\bizdash\backup.bat 으로 저장합니다.
       (경로·저장 위치는 실제 환경에 맞게)

           @echo off
           set D=%date:~0,4%-%date:~5,2%-%date:~8,2%
           "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" ^
             -U bizdash -h localhost -w -Fc bizdash > "C:\backup\bizdash_%D%.dump"

       -w 는 '비밀번호를 묻지 말라' 는 뜻입니다. (가) 의 pgpass 를 씁니다.
       저장 폴더(C:\backup)는 미리 만들어 두세요.

       관리자 명령 창에서 매일 새벽 3시에 돌도록 등록합니다.

           schtasks /create /tn "bizdash 백업" /tr "C:\bizdash\backup.bat" ^
             /sc daily /st 03:00 /ru SYSTEM

       등록됐는지 확인 · 지금 바로 한 번 실행해 보기:

           schtasks /query /tn "bizdash 백업"
           schtasks /run   /tn "bizdash 백업"

       실행 후 C:\backup 에 .dump 파일이 생기면 정상입니다.

     ※ 받아만 두고 끝내지 마세요. 처음 한 번은 실제로 복구해 보고
       자료가 살아나는지 확인해야 진짜 백업입니다.
       복구 방법은 4단계 백업 항목의 pg_restore 를 보세요.

     ※ 회의 사진은 pg_dump 로 받아지지 않습니다.

       사진은 데이터베이스가 아니라 data\uploads 폴더에 파일로 있습니다.
       (데이터베이스에 넣으면 백업 파일이 급격히 커지고 되돌리기도 느려집니다)
       pg_dump 는 데이터베이스만 받으므로 이 폴더를 따로 복사해야 합니다.

       backup.bat 에 아래 한 줄을 더해 두면 함께 받아집니다.

           robocopy "C:\bizdash\app\data\uploads" "C:\backup\uploads" /MIR /NFL /NDL /NJH /NJS

       /MIR 은 지워진 사진까지 맞춰 지웁니다. 그것이 싫으면 /E 로 바꾸세요.

     ※ 오래된 덤프는 쌓이기만 합니다. 디스크가 찰 수 있으니
       가끔 지우거나, 지난 것을 지우는 줄을 backup.bat 에 더하세요.


┌──────────────────────────────────────────────────────────────┐
│ 프론트와 백엔드를 다른 포트로 나누려면 (선택)                 │
└──────────────────────────────────────────────────────────────┘

  지금 구성은 한 포트(80)로 화면과 API 를 모두 내보냅니다.
  이것을 두 포트로 나눌 수 있습니다. 같은 코드·같은 .env 를 쓰고,
  프로세스 두 개가 각각 자기 역할만 맡습니다.

      8080   화면(frontend/dist)만         ROLE=web
      8081   API 와 데이터베이스만         ROLE=api

  역할은 .env 의 ROLE 로 정합니다. 적지 않으면 all (지금처럼 한 포트에서
  둘 다) 입니다. 서버에 Node.js 를 새로 깔 필요는 없습니다 — 화면 쪽도
  같은 파이썬으로 파일만 내보냅니다.

  ※ 나누면 관리할 것이 늘어납니다. 서비스 2개, 방화벽 2개, CORS 설정이
    새로 생기고, 쓰는 사람들의 즐겨찾기도 바뀝니다. 한 포트로 충분하면
    나누지 않는 편이 단순합니다.


─── 1단계.  개발 PC — 화면을 다시 만들어 올립니다 ──────────────

  화면은 "API 가 몇 번 포트에 있는지" 를 빌드할 때 박아 넣습니다.
  서버에서는 고칠 수 없으므로 개발 PC 에서 정해야 합니다.

  frontend/.env.production 을 열어 API 포트를 적습니다.

      VITE_API_PORT=8081

  그다음 화면을 다시 만들어 커밋합니다.

      powershell -ExecutionPolicy Bypass -File scripts\release.ps1
      git add -A
      git commit -m "프론트·백엔드 포트 분리"
      git push

  ※ 이 값과 서버의 ROLE 구성이 어긋나면 화면은 뜨는데 자료가 하나도
    안 나옵니다. 가장 흔한 실수입니다. 한 포트로 쓸 때는 이 값을 비웁니다.


─── 2단계.  서버 PC — 받습니다 ─────────────────────────────────

      bizdash-service.exe stop
      git pull


─── 3단계.  .env 에 CORS_ORIGINS 를 넣습니다 ───────────────────

  화면(8080)과 API(8081)는 포트가 달라 브라우저가 서로 다른 곳으로
  봅니다. 그래서 API 쪽에 "이 주소는 우리 화면이다" 라고 알려 주어야
  합니다. 비워 두면 브라우저가 요청을 막아 자료가 안 나옵니다.

      CORS_ORIGINS=http://10.20.150.128:8080

  쓰는 사람이 여러 주소로 들어온다면 쉼표로 모두 적습니다.
  적지 않은 주소로 들어온 사람만 자료가 안 보이므로, 빠뜨리기 쉽습니다.

      CORS_ORIGINS=http://10.20.150.128:8080,http://서버이름:8080

  ※ ROLE 은 .env 에 적지 않습니다. 두 서비스가 같은 .env 를 함께 쓰므로,
    서비스마다 다른 값을 주어야 해서 아래 xml 에 넣습니다.


─── 4단계.  서비스를 둘로 나눕니다 ─────────────────────────────

  먼저 지금 서비스를 멈추고 지웁니다.

      bizdash-service.exe stop
      bizdash-service.exe uninstall

  ※ stop 을 먼저 하세요. 멈추지 않고 지우면 앱이 그대로 떠서 포트를
    잡고 있어, 다음에 설치할 때 포트 충돌로 막힙니다.

  WinSW 는 실행 파일과 xml 의 이름이 같아야 합니다. 그래서 받아 둔
  파일을 두 개로 복사합니다.

      copy bizdash-service.exe bizdash-web-service.exe
      copy bizdash-service.exe bizdash-api-service.exe

  화면 쪽 — bizdash-web-service.xml

      <service>
        <id>bizdash-web</id>
        <name>사업관리 대시보드 (화면)</name>
        <description>화면 파일만 내보냅니다</description>

        <executable>C:\bizdash\app\.venv\Scripts\python.exe</executable>
        <arguments>-m uvicorn app.main:app --host 0.0.0.0 --port 8080</arguments>
        <workingdirectory>C:\bizdash\app\backend</workingdirectory>

        <env name="PYTHONUTF8" value="1"/>
        <env name="ROLE" value="web"/>

        <onfailure action="restart" delay="5 sec"/>
        <log mode="roll-by-size"/>
      </service>

  API 쪽 — bizdash-api-service.xml  (ROLE 과 포트만 다릅니다)

      <service>
        <id>bizdash-api</id>
        <name>사업관리 대시보드 (API)</name>
        <description>API 와 데이터베이스</description>

        <executable>C:\bizdash\app\.venv\Scripts\python.exe</executable>
        <arguments>-m uvicorn app.main:app --host 0.0.0.0 --port 8081</arguments>
        <workingdirectory>C:\bizdash\app\backend</workingdirectory>

        <env name="PYTHONUTF8" value="1"/>
        <env name="ROLE" value="api"/>

        <onfailure action="restart" delay="5 sec"/>
        <log mode="roll-by-size"/>
      </service>

  등록하고 시작합니다. API 를 먼저 켜세요 — 화면이 먼저 뜨면 그 사이에
  들어온 사람이 자료 없는 화면을 보게 됩니다.

      bizdash-api-service.exe install
      bizdash-api-service.exe start
      bizdash-web-service.exe install
      bizdash-web-service.exe start

  로그는 각각 bizdash-api-service.out.log · bizdash-web-service.out.log
  로 쌓입니다. 어느 쪽이 말썽인지 따로 볼 수 있습니다.


─── 5단계.  방화벽을 두 포트 다 엽니다 ─────────────────────────

  둘 다 열어야 합니다. API(8081)를 빼먹으면 화면은 뜨는데 자료가
  하나도 안 나옵니다 — 증상이 CORS 를 빠뜨린 것과 똑같아 헷갈립니다.

      New-NetFirewallRule -DisplayName "사업관리 대시보드" `
        -Direction Inbound -Protocol TCP -LocalPort 8080,8081 `
        -Action Allow -RemoteAddress 10.20.150.0/23

  예전에 만든 80 번 규칙은 지워도 됩니다.

      Remove-NetFirewallRule -DisplayName "사업관리 대시보드"

  (위 New- 명령을 먼저 돌렸다면 같은 이름이라 새 규칙까지 지워집니다.
   지우는 것을 먼저 하고 새로 만드는 순서로 하세요)


─── 6단계.  확인 ───────────────────────────────────────────────

  두 쪽을 각각 열어 봅니다. role 이 다르게 나와야 정상입니다.

      http://10.20.150.128:8080/api/health    → "role":"web"
      http://10.20.150.128:8081/api/health    → "role":"api"  (db 도 함께)

  그다음 화면으로 들어가 로그인까지 되면 끝입니다.

      http://10.20.150.128:8080

  ※ 쓰는 사람들에게 새 주소를 알려 주세요. 80 번으로는 더 이상 열리지
    않으므로 즐겨찾기를 모두 바꿔야 합니다.


─── 한 포트로 되돌리려면 ───────────────────────────────────────

  1. 두 서비스를 멈추고 지웁니다.

         bizdash-api-service.exe stop
         bizdash-api-service.exe uninstall
         bizdash-web-service.exe stop
         bizdash-web-service.exe uninstall

  2. 개발 PC 에서 frontend/.env.production 의 VITE_API_PORT 를 비우고
     화면을 다시 만들어 올립니다 (release.ps1 → commit → push).
     서버에서 git pull 합니다.

  3. .env 의 CORS_ORIGINS 를 비웁니다.

  4. 원래 bizdash-service.xml 로 다시 등록합니다 (위 'Windows' 절).


─── 나누고 나서 생기는 증상과 원인 ─────────────────────────────

  ▷ 화면은 뜨는데 자료가 하나도 안 나옵니다
      셋 중 하나입니다. 브라우저에서 F12 → 콘솔을 보면 구분됩니다.
      · CORS 오류가 보임        → .env 의 CORS_ORIGINS (3단계)
      · 연결 실패로 보임        → 방화벽 8081 (5단계) 또는 API 서비스가 꺼짐
      · 엉뚱한 포트로 요청함    → 화면 빌드의 VITE_API_PORT (1단계)

  ▷ 로그인이 자꾸 풀립니다
      쿠키는 포트를 가리지 않으므로 보통 이것 때문은 아닙니다.
      .env 의 SECRET_KEY 가 두 서비스에서 같은지 보세요 — 같은 .env 를
      쓰므로 보통 같습니다. COOKIE_SECURE 가 true 인데 http 로 쓰고
      있으면 쿠키가 아예 저장되지 않습니다.

  ▷ 회의록 문서 받기·사진이 안 됩니다
      이것들은 API(8081)에서 직접 받아 갑니다. 방화벽에 8081 이
      열려 있는지 확인하세요.


┌──────────────────────────────────────────────────────────────┐
│ (참고) 리눅스 서버라면                                        │
└──────────────────────────────────────────────────────────────┘

  이 서버는 Windows 라 위의 'Windows' 절을 따르면 됩니다.
  혹시 리눅스에 올릴 일이 있으면 WinSW 대신 systemd 를 씁니다.
  /etc/systemd/system/bizdash.service 를 아래처럼 만들고
  (경로·사용자·포트는 실제 환경에 맞게):

      [Unit]
      Description=사업관리 대시보드
      After=network.target

      [Service]
      User=bizdash
      WorkingDirectory=/opt/bizdash/backend
      EnvironmentFile=/opt/bizdash/.env
      Environment=PYTHONUTF8=1
      ExecStart=/opt/bizdash/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
      Restart=always
      RestartSec=5

      [Install]
      WantedBy=multi-user.target

  등록 · 시작 · 로그:

      sudo systemctl daemon-reload
      sudo systemctl enable --now bizdash
      sudo journalctl -u bizdash -f

┌──────────────────────────────────────────────────────────────┐
│ 고친 뒤 서버에 반영하기                                       │
└──────────────────────────────────────────────────────────────┘

  개발 PC 에서 고치고, 서버는 받아서 다시 시작합니다.


  ── 개발 PC 에서 ──

    powershell -ExecutionPolicy Bypass -File scripts\release.ps1

  macOS · Linux 개발 PC 라면 (하는 일은 같습니다):

    bash scripts/release.sh

  테스트 · 시안 대조 · 화면 빌드를 한 번에 하고, 바뀐 화면을 커밋
  대상에 올려 줍니다. 통과하지 못하면 거기서 멈춥니다.

  화면 빌드를 빠뜨리면 서버가 새 코드에 옛날 화면을 쓰게 되므로
  이 스크립트로 돌리시는 편이 안전합니다.

  끝나면 올립니다.

      git add -A
      git commit -m "무엇을 고쳤는지"
      git push


  ── 서버 PC 에서 ──

  1) 먼저 백업합니다. 되돌릴 곳이 있어야 마음 놓고 올립니다.

         pg_dump -U bizdash -Fc bizdash > C:\backup\update전_2026-09-01.dump

  2) 서비스를 멈춥니다.

         bizdash-service.exe stop

  3) 받습니다.

         git pull

  4) 라이브러리가 늘었으면 (requirements.txt 가 바뀐 경우)

         .venv\Scripts\pip install -r requirements.txt

  5) 표 구조가 바뀌었으면 — 아래 ※ 를 꼭 읽어 주세요

         cd backend
         ..\.venv\Scripts\alembic upgrade head

  6) 다시 시작하고 화면을 열어 확인합니다.

         bizdash-service.exe start


  ※ 표 구조가 바뀌었는지 어떻게 아나

    backend/alembic/versions/ 에 파일이 새로 생겼으면 바뀐 것입니다.
    서비스는 없는 표만 자동으로 만들고, 컬럼이 늘거나 바뀐 것은
    반영하지 않습니다. 5단계를 빠뜨리면 '그런 컬럼이 없다' 는 오류가
    납니다. 개발 PC 에서는 멀쩡하던 것이 서버에서만 터지는 경우가
    대개 이것입니다.


  ※ 잘못되면

    git log 로 직전 커밋을 찾아 되돌리고 서비스를 다시 시작합니다.

        git reset --hard 직전커밋
        bizdash-service.exe start

    자료까지 되돌려야 하면 1) 에서 받아 둔 백업을 복구합니다.
    복구 방법은 4단계 백업 항목의 pg_restore 를 보세요.


┌──────────────────────────────────────────────────────────────┐
│ https 로 서비스하려면 (선택)                                  │
└──────────────────────────────────────────────────────────────┘

  사내망 5명이 쓰는 지금 구성은 http 로 충분합니다. 앞단 웹서버 없이
  이 서버 하나가 화면까지 내보냅니다. 아래는 https 가 꼭 필요할 때만
  보세요.

  사내 IP(도메인 없음)에서는 https 가 생각보다 번거롭습니다. 공인
  도메인이 없어 인증서 자동 발급이 안 되므로, 둘 중 하나가 필요합니다.

    · 사내 인증기관(CA)에서 이 서버 IP 용 인증서를 발급받기
    · 자체 서명 인증서를 만들고 쓰는 PC 마다 신뢰하도록 배포하기

  인증서를 준비했다면, 앞단에 Caddy 나 Nginx 같은 웹서버를 두고
  이 앱(로컬 포트)으로 넘기면 됩니다. 그때는 .env 에서
  COOKIE_SECURE=true 로 바꿉니다.

┌──────────────────────────────────────────────────────────────┐
│ 문제가 생기면                                                 │
└──────────────────────────────────────────────────────────────┘

  ▷ 화면이 안 뜨고 글자만 나옵니다
      frontend/dist 폴더가 있는지 확인해 주세요.
      저장소에 함께 들어 있으므로, 없다면 제대로 받아지지 않은 것입니다.

  ▷ 고친 내용이 화면에 안 보입니다
      개발 PC 에서 화면 빌드를 빠뜨렸을 수 있습니다.
      release.ps1 (Windows) 또는 release.sh (mac·Linux) 로
      다시 만들어 올려 주세요.

  ▷ 공고 수집이 안 됩니다
      서버가 외부 인터넷에 나갈 수 있어야 합니다.
      아래 4곳에 접속되는지 확인해 주세요.
          www.khidi.or.kr    www.kohi.or.kr
          www.khis.kr        www.ntis.go.kr

  ▷ 서비스는 켜졌는데 다른 PC 에서 접속이 안 됩니다
      방화벽 규칙을 넣지 않았을 가능성이 큽니다. 위 4) 를 보세요.
      서버 PC 에서 http://localhost 는 되는데 다른 PC 만 안 되면
      거의 방화벽입니다.

  ▷ 서비스가 켜지자마자 꺼집니다 (Windows)
      bizdash-service.out.log 를 열어 보세요.
      한글이 깨진 자리에서 멈춰 있으면 xml 의 PYTHONUTF8 설정이
      빠진 것입니다.

  ▷ 비밀번호를 잊었습니다
      .venv\Scripts\python.exe scripts\set_password.py 로 다시 정하면 됩니다.

  ▷ 로그인 화면으로 돌아가고 싶습니다
      주소 뒤에 ?logout 을 붙입니다.  예) http://localhost:8000/?logout

  ▷ 잘 돌아가는지 확인하고 싶습니다
      cd backend
      ..\.venv\Scripts\python.exe -m pytest
      → 113건 전부 통과하면 정상입니다.
