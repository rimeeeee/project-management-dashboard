# 공고 수집

## 어디서 가져오나

| 기관 | 방식 | 주소 |
|---|---|---|
| 한국보건의료정보원 | RSS | `khis.kr/rss/board.es?mid=a10301000000&bid=0001` |
| 한국보건복지인재원 | 게시판 | `kohi.or.kr/user/bbs/BD_selectBbsList.do?q_bbsCode=1013` |
| 한국보건산업진흥원 | 게시판 | `khidi.or.kr/board?menuId=MENU01108` |
| NTIS 통합공고 | RSS | `ntis.go.kr/rndgate/unRndRss.xml` |

## 언제 도나

**기본은 자동 수집을 끄고, 화면의 [지금 수집] 버튼을 누를 때만 받습니다.**
필요한 때에 사람이 직접 돌리는 편이 예측하기 쉬워서입니다.

자동으로 돌리고 싶으면 `.env` 에서 켭니다.

```
COLLECTOR_ENABLED=true
COLLECTOR_CRON=0 6 * * 1,4
```

크론은 `분 시 일 월 요일` 순서입니다. `0 6 * * 1,4` 는 **매주 월·목 오전 6시**
(요일 번호: 0=일 1=월 2=화 3=수 4=목 5=금 6=토). 화면에는 이 표기를 그대로
띄우지 않고 "매주 월·목 오전 6시" 처럼 풀어서 보여 줍니다.

서버를 여러 대로 늘리면 한 대에서만 켜세요. 여러 대가 동시에 돌면 수집이 겹칩니다.

## 기관별로 얼마나 가져올 수 있는가 (2026-08 실측)

수집기간은 `.env` 의 `COLLECT_DAYS` 로 정합니다(기본 **365일**). 다만 기관마다
게시판이 밖으로 내주는 양이 달라서, 설정을 늘려도 더 안 나오는 곳이 있습니다.

| 기관 | 실제로 받는 양 | 무엇이 한계인가 |
|---|---|---|
| 한국보건복지인재원 | **57건 · 약 1년** | 쪽당 50건이라 1년이 2쪽. 설정대로 나옵니다 |
| 한국보건의료정보원 | **43건 · 약 1년** | RSS 가 2020년치까지 271건을 한 번에 줍니다. 설정대로 자릅니다 |
| 한국보건산업진흥원 | **100건 · 약 6.5개월** | **게시판 자체의 한계** (아래) |
| NTIS 통합공고 | 138건 · 90일 | `NTIS_DAYS` 로 따로 관리 (아래) |

### 진흥원이 6.5개월에서 멈추는 이유

`COLLECT_DAYS` 를 1년으로 올려도 더 안 나옵니다. 게시판이 그만큼만 내주기 때문입니다.

- `pageNum` 이 **10에서 순환**합니다. 11쪽은 1쪽, 16쪽은 6쪽과 같은 내용입니다
- `rowCnt`(쪽당 건수)를 50·100 으로 줘도 10건씩만 옵니다
- `schStartDate` / `schEndDate`(기간 검색), `minIndex` / `maxIndex` 는
  GET·POST 어느 쪽으로도 무시됩니다
- `/rss.do` 는 10건만 줍니다

그래서 `BOARD_PAGES` 를 12로 두었습니다. 더 올려도 같은 내용을 다시 받을 뿐입니다.
더 과거가 꼭 필요하면 진흥원에 **공고 목록 API 나 RSS 제공**을 문의하는 것이
유일한 방법입니다.

## 손대면 안 되는 부분

`app/collector/fetch.py` 의 `fetch()` 에 들어 있는 **응답 잘림 대응** 입니다.

한국보건복지인재원 서버는 응답을 끝까지 보내지 않고 끊는 일이 잦습니다.
실제 페이지를 확인해 보니 좌측 메뉴가 커서 글 목록이 페이지의 75% 지점에서야
시작하고, 끊기는 자리가 딱 그 부근입니다. 그래서

- 끊기면 다시 받아 보고 그중 **가장 많이 받은** 응답을 씁니다 (최대 4회)
- 한 쪽에 50건씩 담습니다 (`q_rowPerPage=50`) — 잘려도 건지는 글이 많아집니다
- **잘린 쪽은 '글이 없는 쪽'으로 보지 않습니다.** 그렇게 보면 일찍 멈춰서
  오히려 덜 걷힙니다 (원본 스크립트 v8 에서 고친 문제입니다)

## 수집 단계에서는 걸러내지 않습니다

원본 스크립트에는 키워드 필터가 있었지만 **껐습니다.** 전량 저장하고
걸러내기는 화면에서만 합니다. 나중에 "그때 그 공고 있었는데 왜 없지?" 하는
상황을 막기 위해서입니다. NTIS 를 붙이면 건수가 크게 늘지만, 화면이 쪽을
나눠 받으므로 문제가 되지 않습니다.

## 직접 등록한 공고는 덮어쓰지 않습니다

목록에는 공고금액·문의처가 없어 손으로 채워 넣게 됩니다. 한 번 손대면
`source` 가 `manual` 이 되어 다음 수집이 건드리지 않습니다.

## 수집이 멈추면

화면 위에 마지막 수집 시각과 건수가 늘 보입니다.

- **초록 점** — 정상
- **노란 점** — 일부 서버가 응답을 끊었거나 실패한 소스가 있음
- **빨간 점** — 수집 기록이 아예 없음

수집이 조용히 멈춰 있는데 아무도 모르는 상황이 제일 위험해서 넣은 표시입니다.

## 서버가 바깥 인터넷에 못 나가면

수집이 아예 되지 않습니다. 전산실에 **서버에서 외부 인터넷으로 나갈 수 있는지**
먼저 확인해야 합니다.

(붙여넣기로 넣는 [수집 데이터 불러오기] 화면이 있었지만 지웠습니다.
 필요해지면 `app/collector/runner.py` 의 `upsert()` 가 그대로 있으므로
 다시 붙이는 것은 어렵지 않습니다.)


## NTIS 통합공고 — 확인한 것

XSL 샘플(`unRndRss.xsl`)에는 `author`/`title`/`link`/`pubDate` 만 쓰여 있어서
마감일·공고금액이 없을 줄 알았는데, **실제 응답에는 있었습니다.**
원문은 `docs/ntis/unRndRss-원문.xml` 에 남겨 두었습니다.

| 태그 | 뜻 | 예 |
|---|---|---|
| `title` | 공고명 | 2026년 사회문제해결형 R&BD 지원사업 시행 공고 |
| `link` | 원문 주소 | `…/view.do?roRndUid=1276553` |
| `author` | 공고기관(부처) | 과학기술정보통신부 |
| `category` | 전문기관 | 연구개발특구진흥재단 |
| `pubDate` | 공고일 | `2026.08.21` |
| `appbegin` | **접수 시작일** | `2026-08-21` |
| `appdue` | **접수 마감일** | `2026-09-21` |
| `budget` | **공고금액(원)** | `510000000` |
| `totCnt` | 전체 건수 | 10,230 |

그래서 기관 게시판과 달리 제목에서 마감일을 뽑아낼 필요가 없습니다.
`appdue` 가 빈 공고만 제목에서 뽑아 봅니다.

실제 100건으로 확인한 결과: **마감일 100/100, 공고금액 68/100**
(기술수요조사처럼 금액이 없는 공고가 있습니다 — 임의로 채우지 않습니다.)

### 옵션이 실제로 어떻게 동작하는지

| 옵션 | 확인된 동작 |
|---|---|
| `prt` | 가져올 개수. **최대 100** (200·500 을 넣어도 100건만 옵니다) |
| `Fi` | 전체 오프셋이 **아닙니다.** `prt` 로 가져온 묶음 안의 시작 행입니다. `prt=3&Fi=4` 는 0건 |
| `dt=YYYYMMDD` | 그 날짜에 올라온 공고만 |
| `bbs=true` | `description`(본문)만 더 붙습니다. 응답이 크게 늘어나는데 마감일·금액이 이미 있어 **쓰지 않습니다** |

`prt`/`Fi` 로는 최신 100건 너머로 갈 수 없습니다. 그래서

수집할 때 이렇게 합니다.

1. `prt=100` 으로 최신 100건을 받습니다
2. 그 100건이 **덮지 못한 이전 날짜만** `dt=YYYYMMDD` 로 하루씩 채웁니다

처음에는 1번만 했는데, 재어 보니 최신 100건이 **72일치**밖에 안 되어
수집기간 90일에서 18일이 빠졌습니다(**38건 누락**). 그래서 2번을 붙였습니다.

남은 날짜만 훑기 때문에 90일을 통째로 도는 것(39초)보다 빠릅니다.
실제로 **138건을 10초**에 받습니다.

더 과거를 채우려면 `scripts/ntis_backfill.py` 를 씁니다.

```bash
.venv/bin/python scripts/ntis_backfill.py --days 180
```


## SSL 인증서 (macOS 에서 개발할 때)

macOS 에 python.org 파이썬을 설치하면 시스템 인증서를 못 찾아
`[SSL: CERTIFICATE_VERIFY_FAILED]` 로 수집이 통째로 실패합니다.

`backend/app/core/http.py` 의 `ssl_context()` 를 쓰면 certifi 인증서를 씁니다.
**바깥에 요청하는 코드는 모두 이 함수를 쓰세요.**
운영 서버(리눅스)에서는 시스템 인증서가 정상이라 어느 쪽이든 동작합니다.
