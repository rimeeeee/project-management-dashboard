# 공고 수집

## 어디서 가져오나

| 기관 | 방식 | 주소 |
|---|---|---|
| 한국보건의료정보원 | RSS | `khis.kr/rss/board.es?mid=a10301000000&bid=0001` |
| 한국보건복지인재원 | 게시판 | `kohi.or.kr/user/bbs/BD_selectBbsList.do?q_bbsCode=1013` |
| 한국보건산업진흥원 | 게시판 | `khidi.or.kr/board?menuId=MENU01108` |
| NTIS 통합공고 | RSS | `ntis.go.kr/rndgate/unRndRss.xml` |

## 언제 도나

기본값은 **월·목 06:00 (한국시간)** 입니다. `.env` 의 `COLLECTOR_CRON` 으로 바꿉니다.
화면의 [지금 수집] 버튼으로 언제든 직접 돌릴 수도 있습니다.

서버를 여러 대로 늘리면 한 대에서만 `COLLECTOR_ENABLED=true` 로 두세요.
여러 대가 동시에 돌면 같은 수집이 겹칩니다.

## 손대면 안 되는 부분

`app/collector/fetch.py` 의 `fetch()` 에 들어 있는 **응답 잘림 대응** 입니다.

한국보건복지인재원 서버는 응답을 끝까지 보내지 않고 끊는 일이 잦습니다.
실제 페이지를 확인해 보니 좌측 메뉴가 커서 글 목록이 페이지의 75% 지점에서야
시작하고, 끊기는 자리가 딱 그 부근입니다. 그래서

- 끊기면 다시 받아 보고 그중 **가장 많이 받은** 응답을 씁니다 (최대 4회)
- 한 쪽에 50건씩 담습니다 (`q_rowPerPage=50`) — 잘려도 건지는 글이 많아집니다
- **잘린 쪽은 '글이 없는 쪽'으로 보지 않습니다.** 그렇게 보면 일찍 멈춰서
  오히려 덜 걷힙니다 (원본 스크립트 v8 에서 고친 문제입니다)

## 수집 단계에서는 걸러내지 않습니다

원본 스크립트에는 키워드 필터가 있었지만 **껐습니다.** 전량 저장하고
걸러내기는 화면에서만 합니다. 나중에 "그때 그 공고 있었는데 왜 없지?" 하는
상황을 막기 위해서입니다. NTIS 를 붙이면 건수가 크게 늘지만, 화면이 쪽을
나눠 받으므로 문제가 되지 않습니다.

## 직접 등록한 공고는 덮어쓰지 않습니다

목록에는 공고금액·문의처가 없어 손으로 채워 넣게 됩니다. 한 번 손대면
`source` 가 `manual` 이 되어 다음 수집이 건드리지 않습니다.

## 수집이 멈추면

화면 위에 마지막 수집 시각과 건수가 늘 보입니다.

- **초록 점** — 정상
- **노란 점** — 일부 서버가 응답을 끊었거나 실패한 소스가 있음
- **빨간 점** — 수집 기록이 아예 없음

수집이 조용히 멈춰 있는데 아무도 모르는 상황이 제일 위험해서 넣은 표시입니다.

## 서버가 바깥 인터넷에 못 나가면

[수집 데이터 불러오기] 를 남겨 두었습니다. 인터넷이 되는 PC 에서
`docs/prototype/공고수집_v9.py` 를 돌린 뒤 만들어진 `공고데이터.json` 을
붙여넣으면 됩니다.


## NTIS 통합공고 — 확인한 것

XSL 샘플(`unRndRss.xsl`)에는 `author`/`title`/`link`/`pubDate` 만 쓰여 있어서
마감일·공고금액이 없을 줄 알았는데, **실제 응답에는 있었습니다.**
원문은 `docs/ntis/unRndRss-원문.xml` 에 남겨 두었습니다.

| 태그 | 뜻 | 예 |
|---|---|---|
| `title` | 공고명 | 2026년 사회문제해결형 R&BD 지원사업 시행 공고 |
| `link` | 원문 주소 | `…/view.do?roRndUid=1276553` |
| `author` | 공고기관(부처) | 과학기술정보통신부 |
| `category` | 전문기관 | 연구개발특구진흥재단 |
| `pubDate` | 공고일 | `2026.08.21` |
| `appbegin` | **접수 시작일** | `2026-08-21` |
| `appdue` | **접수 마감일** | `2026-09-21` |
| `budget` | **공고금액(원)** | `510000000` |
| `totCnt` | 전체 건수 | 10,230 |

그래서 기관 게시판과 달리 제목에서 마감일을 뽑아낼 필요가 없습니다.
`appdue` 가 빈 공고만 제목에서 뽑아 봅니다.

실제 100건으로 확인한 결과: **마감일 100/100, 공고금액 68/100**
(기술수요조사처럼 금액이 없는 공고가 있습니다 — 임의로 채우지 않습니다.)

### 옵션이 실제로 어떻게 동작하는지

| 옵션 | 확인된 동작 |
|---|---|
| `prt` | 가져올 개수. **최대 100** (200·500 을 넣어도 100건만 옵니다) |
| `Fi` | 전체 오프셋이 **아닙니다.** `prt` 로 가져온 묶음 안의 시작 행입니다. `prt=3&Fi=4` 는 0건 |
| `dt=YYYYMMDD` | 그 날짜에 올라온 공고만 |
| `bbs=true` | `description`(본문)만 더 붙습니다. 응답이 크게 늘어나는데 마감일·금액이 이미 있어 **쓰지 않습니다** |

`prt`/`Fi` 로는 최신 100건 너머로 갈 수 없습니다. 그래서

- **정기 수집은 `prt=100`** — 하루에 새로 올라오는 것이 두어 건이라 주 2회 수집이면 충분합니다
- **지난 공고는 `scripts/ntis_backfill.py`** — `dt=` 로 하루씩 받습니다.
  처음 도입할 때 한 번, 또는 수집이 오래 멈춰 있었을 때 돌립니다.

```bash
.venv/bin/python scripts/ntis_backfill.py --days 90
```
