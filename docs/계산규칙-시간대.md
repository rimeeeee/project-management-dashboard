# 계획 진척률은 한국시간 기준입니다

계산 규칙을 손보게 될 분을 위한 기록입니다.
`backend/app/core/calc.py` 의 `calc_planned()` 가 이 내용입니다.

## 어떤 차이가 있었나

디자인 시안(프로토타입)은 계획 진척률을 이렇게 계산했습니다.

```js
const s = new Date(p.start), e = new Date(p.end), n = new Date();
return Math.round(clamp((n - s) / (e - s), 0, 1) * 100);
```

`new Date("2026-06-01")` 은 자바스크립트에서 **UTC 자정**으로 읽힙니다.
한국시간으로는 6월 1일 **오전 9시**입니다. 즉 시안은 사업이 시작일 오전 9시에
시작한 것으로 치고 있었습니다. 의도라기보다 자바스크립트의 날짜 해석 방식
때문에 그렇게 된 것으로 보입니다.

## 얼마나 다른가

`scripts/verify/run.py` 로 1,200건을 대조한 결과입니다.

| | |
|---|---|
| 다른 날 | 1,200건 중 **72건 (6.0%)** |
| 차이 크기 | **항상 정확히 1%p** (한국시간 쪽이 1 큼) |

상태 배지가 계획 대비 −5%p / −15%p 를 경계로 갈리므로, 경계에 딱 걸친 사업은
어떤 날 '정상' 대신 '점검 필요'로 보일 수 있습니다.

## 한국시간으로 정한 이유

1. 사업이 시작일 오전 9시에 시작한다고 볼 근거가 없습니다.
2. 공고 마감 판정(`접수중`/`마감`)도 같은 '오늘'을 쓰는데, 그쪽은 반드시
   한국시간이어야 합니다. 두 기준이 서로 다르면 나중에 더 헷갈립니다.

시안과 똑같이 맞춰야 할 일이 생기면 `calc_planned()` 한 함수만
UTC 자정 기준으로 바꾸면 됩니다.

`scripts/verify/run.py` 의 3번 항목이 이 차이를 계속 감시합니다.
1%p 를 넘으면 실패로 알려 줍니다.
