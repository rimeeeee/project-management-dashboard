================================================================
 프론트·백엔드 포트 분리 — 서버 작업 순서
================================================================

 한 포트(80)로 쓰던 것을 두 포트로 나눕니다.

     8080   화면
     8081   API

 이 파일은 전환할 때 한 번 쓰는 작업표입니다.
 평소 설치·운영 설명은 docs/설치방법.txt 를 보세요.


┌──────────────────────────────────────────────────────────────┐
│ 시작하기 전에                                                 │
└──────────────────────────────────────────────────────────────┘

  ■ 관리자 PowerShell 로 하세요 (명령 프롬프트 아님)

    시작 단추 오른쪽 클릭  →  "터미널(관리자)" 또는
                              "Windows PowerShell(관리자)"

    명령 프롬프트(cmd)에서는 방화벽·상태 확인 명령이 안 됩니다.
    PowerShell 에서는 아래 명령 전부가 됩니다. 창 하나로 끝납니다.

  ■ 쓰는 사람이 없는 시간에 하세요

    중간에 5~10분 접속이 안 됩니다.

  ■ 아래 값이 실제와 맞는지 먼저 확인하세요

    서버 IP        10.20.150.128
    설치 폴더      C:\bizdash\app
    서비스 폴더    C:\bizdash          (bizdash-service.exe 가 있는 곳)
    사내 대역      10.20.150.0/23
    백업 폴더      C:\backup

    서비스 폴더를 모르면 이렇게 찾습니다.

        Get-ChildItem C:\bizdash -Recurse -Filter "bizdash-service.*" |
          Select-Object FullName

    다르면 아래 명령의 경로를 바꿔 쓰세요.

  ■ 전체 20~30분 걸립니다. 중간에 멈추지 마세요.

    3단계(git pull)만 하고 멈추면 화면은 뜨는데 자료가 안 나옵니다.
    새 화면 파일이 8081 로 물어보는데 8081 이 아직 없기 때문입니다.


┌──────────────────────────────────────────────────────────────┐
│ 0단계.  개발 PC 에서 (서버 아님)                              │
└──────────────────────────────────────────────────────────────┘

  새 코드를 올려 두어야 서버가 받을 수 있습니다.

      git push

  이미 올렸으면 넘어가세요.


┌──────────────────────────────────────────────────────────────┐
│ 1단계.  백업                                                  │
└──────────────────────────────────────────────────────────────┘

  되돌릴 자리를 먼저 만듭니다. 날짜는 오늘 날짜로 바꿔 쓰세요.

      pg_dump -U bizdash -Fc bizdash > C:\backup\전환전_2026-11-02.dump

  pg_dump 를 못 찾는다고 하면 경로째 씁니다.

      & "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U bizdash -Fc bizdash > C:\backup\전환전_2026-11-02.dump

  ─ 확인 ─  파일이 생겼고 크기가 0 이 아니어야 합니다.

      Get-ChildItem C:\backup | Select-Object Name, Length, LastWriteTime


┌──────────────────────────────────────────────────────────────┐
│ 2단계.  지금 서비스 멈추기                                    │
└──────────────────────────────────────────────────────────────┘

      cd C:\bizdash
      .\bizdash-service.exe stop

  ※ PowerShell 에서는 앞에 .\ 를 붙여야 합니다.

  ─ 확인 ─  Stopped 로 나와야 합니다.

      .\bizdash-service.exe status


┌──────────────────────────────────────────────────────────────┐
│ 3단계.  새 코드 받기                                          │
└──────────────────────────────────────────────────────────────┘

      cd C:\bizdash\app
      git pull

  ─ 확인 ─  아래 파일이 새로 생겨 있어야 합니다.

      Test-Path C:\bizdash\app\frontend\.env.production

  True 가 나와야 합니다. False 면 git pull 이 안 된 것입니다.


┌──────────────────────────────────────────────────────────────┐
│ 4단계.  .env 고치기  ← 가장 많이 빠뜨리는 곳                  │
└──────────────────────────────────────────────────────────────┘

      notepad C:\bizdash\app\.env

  CORS_ORIGINS 로 시작하는 줄을 찾아 아래처럼 바꿉니다.

      CORS_ORIGINS=http://10.20.150.128:8080

  저장하고 닫습니다.

  왜 필요한가
      화면(8080)과 API(8081)는 포트가 달라서 브라우저가 서로 남으로
      봅니다. 이 값으로 "저 주소는 우리 화면이다" 라고 알려 주는
      것입니다. 비워 두면 브라우저가 막아서 자료가 하나도 안 나옵니다.

  여러 주소로 들어온다면 쉼표로 모두 적습니다.
  적지 않은 주소로 들어온 사람만 자료가 안 보입니다.

      CORS_ORIGINS=http://10.20.150.128:8080,http://서버이름:8080

  ※ ROLE 은 .env 에 적지 마세요.
    두 서비스가 이 파일을 함께 쓰므로 서비스마다 다른 값이 필요합니다.
    그래서 5단계의 xml 에 넣습니다.

  ─ 확인 ─

      Select-String -Path C:\bizdash\app\.env -Pattern "CORS_ORIGINS"


┌──────────────────────────────────────────────────────────────┐
│ 5단계.  서비스 파일 2개 만들기                                │
└──────────────────────────────────────────────────────────────┘

  WinSW 는 exe 와 xml 의 이름이 같아야 합니다. exe 를 두 개로 복사합니다.

      cd C:\bizdash
      Copy-Item bizdash-service.exe bizdash-web-service.exe
      Copy-Item bizdash-service.exe bizdash-api-service.exe

  그다음 같은 폴더에 xml 두 개를 만듭니다.
  아래 두 명령을 그대로 붙여 넣으면 파일이 만들어집니다.
  (@' 와 '@ 까지 같이 복사하세요. '@ 는 줄 맨 앞에 와야 합니다)


  ── 화면 쪽 (8080) ──

@'
<service>
  <id>bizdash-web</id>
  <name>사업관리 대시보드 (화면)</name>
  <description>화면 파일만 내보냅니다</description>

  <executable>C:\bizdash\app\.venv\Scripts\python.exe</executable>
  <arguments>-m uvicorn app.main:app --host 0.0.0.0 --port 8080</arguments>
  <workingdirectory>C:\bizdash\app\backend</workingdirectory>

  <!-- 이것이 없으면 한글 로그를 만나는 순간 서버가 멈춥니다 -->
  <env name="PYTHONUTF8" value="1"/>
  <env name="ROLE" value="web"/>

  <onfailure action="restart" delay="5 sec"/>
  <log mode="roll-by-size"/>
</service>
'@ | Out-File -Encoding utf8 C:\bizdash\bizdash-web-service.xml


  ── API 쪽 (8081) ──

@'
<service>
  <id>bizdash-api</id>
  <name>사업관리 대시보드 (API)</name>
  <description>API 와 데이터베이스</description>

  <executable>C:\bizdash\app\.venv\Scripts\python.exe</executable>
  <arguments>-m uvicorn app.main:app --host 0.0.0.0 --port 8081</arguments>
  <workingdirectory>C:\bizdash\app\backend</workingdirectory>

  <!-- 이것이 없으면 한글 로그를 만나는 순간 서버가 멈춥니다 -->
  <env name="PYTHONUTF8" value="1"/>
  <env name="ROLE" value="api"/>

  <onfailure action="restart" delay="5 sec"/>
  <log mode="roll-by-size"/>
</service>
'@ | Out-File -Encoding utf8 C:\bizdash\bizdash-api-service.xml


  두 파일의 차이는 id · port · ROLE 세 군데뿐입니다.

  ※ 붙여넣기가 잘 안 되면 (여러 줄 붙여넣기는 가끔 말썽입니다)
    메모장으로 만들어도 됩니다. 위 <service> ... </service> 부분만
    복사해 넣고 저장하세요.

        notepad C:\bizdash\bizdash-web-service.xml
        notepad C:\bizdash\bizdash-api-service.xml

    "파일을 찾을 수 없습니다 — 새로 만들까요?" 가 나오면 예 를 누릅니다.
    저장할 때 파일 형식을 '모든 파일' 로 두어야 .txt 가 붙지 않습니다.

  ─ 확인 ─  파일 4개(exe 2 · xml 2)가 있어야 합니다.

      Get-ChildItem C:\bizdash\bizdash-*-service.* | Select-Object Name, Length


┌──────────────────────────────────────────────────────────────┐
│ 6단계.  기존 서비스 지우기                                    │
└──────────────────────────────────────────────────────────────┘

      cd C:\bizdash
      .\bizdash-service.exe uninstall

  ※ 2단계에서 stop 을 먼저 했습니다. 멈추지 않고 지우면 앱이 그대로
    떠서 포트를 잡고 있어, 다음에 설치할 때 포트 충돌로 막힙니다.
    혹시 그렇게 됐으면 아래로 찾아 끝냅니다.

      Get-NetTCPConnection -LocalPort 80 -State Listen |
        Select-Object OwningProcess
      Stop-Process -Id 위에서나온번호 -Force


┌──────────────────────────────────────────────────────────────┐
│ 7단계.  새 서비스 2개 등록                                    │
└──────────────────────────────────────────────────────────────┘

  API 를 먼저 켜세요. 화면이 먼저 뜨면 그 사이 들어온 사람이
  자료 없는 화면을 보게 됩니다.

      .\bizdash-api-service.exe install
      .\bizdash-api-service.exe start

      .\bizdash-web-service.exe install
      .\bizdash-web-service.exe start

  ─ 확인 ─  둘 다 Started 여야 합니다.

      .\bizdash-api-service.exe status
      .\bizdash-web-service.exe status


┌──────────────────────────────────────────────────────────────┐
│ 8단계.  서버 PC 에서 먼저 확인 (방화벽 건드리기 전)           │
└──────────────────────────────────────────────────────────────┘

  방화벽을 고치기 전에 서버 자신에서 되는지 봅니다.
  여기서 안 되면 방화벽 문제가 아니라 설정 문제입니다.

      Invoke-RestMethod http://localhost:8080/api/health
      Invoke-RestMethod http://localhost:8081/api/health

  ─ 기대하는 결과 ─

      8080 →  role 이 web
      8081 →  role 이 api   (db 값도 함께 나옵니다)

  안 나오면 로그를 봅니다. 어느 쪽이 말썽인지 따로 볼 수 있습니다.

      Get-Content C:\bizdash\bizdash-api-service.out.log -Tail 30
      Get-Content C:\bizdash\bizdash-web-service.out.log -Tail 30

  자주 나오는 것
      · ROLE 은 ... 중 하나여야 합니다  →  xml 의 ROLE 오타
      · 한글이 깨진 자리에서 멈춤        →  xml 의 PYTHONUTF8 누락
      · 포트가 이미 쓰이고 있다          →  6단계를 건너뛴 것


┌──────────────────────────────────────────────────────────────┐
│ 9단계.  방화벽                                                │
└──────────────────────────────────────────────────────────────┘

  ※ 지우기를 먼저, 만들기를 나중에 하세요.
    이름이 같아서 순서가 바뀌면 새로 만든 규칙까지 지워집니다.

      Remove-NetFirewallRule -DisplayName "사업관리 대시보드" -ErrorAction SilentlyContinue

      New-NetFirewallRule -DisplayName "사업관리 대시보드" `
        -Direction Inbound -Protocol TCP -LocalPort 8080,8081 `
        -Action Allow -RemoteAddress 10.20.150.0/23

  ※ 첫 줄에 -ErrorAction SilentlyContinue 를 붙였습니다. 그 이름의 규칙이
    없어도 그냥 넘어가게 하려는 것입니다 (없으면 빨간 오류가 납니다).

  8081 을 빼먹지 마세요. 화면은 뜨는데 자료가 안 나옵니다.

  ─ 확인 ─  8080, 8081 둘 다 나와야 합니다.

      Get-NetFirewallRule -DisplayName "사업관리 대시보드" |
        Get-NetFirewallPortFilter | Select-Object LocalPort


┌──────────────────────────────────────────────────────────────┐
│ 10단계.  다른 PC 에서 확인                                    │
└──────────────────────────────────────────────────────────────┘

  본인 PC 브라우저에서 들어갑니다.

      http://10.20.150.128:8080

  로그인하고 사업 목록이 나오면 끝났습니다.

  확인해 볼 것
      · 사업 목록이 보이는지
      · 사업 하나를 열어 보고 입력 화면이 뜨는지
      · 회의록 탭에서 문서 받기가 되는지   (8081 로 직접 받아 갑니다)
      · 회의 사진이 보이는지                (8081 로 직접 받아 갑니다)


┌──────────────────────────────────────────────────────────────┐
│ 11단계.  공지                                                 │
└──────────────────────────────────────────────────────────────┘

  쓰시는 분들께 알려 주세요.

      주소가 http://10.20.150.128 에서
             http://10.20.150.128:8080 으로 바뀌었습니다.
      즐겨찾기를 다시 등록해 주세요.

  예전 주소(80번)로는 더 이상 열리지 않습니다.


┌──────────────────────────────────────────────────────────────┐
│ 증상별 원인 찾기                                              │
└──────────────────────────────────────────────────────────────┘

  화면에서 F12 를 눌러 Console 탭을 보면 구분됩니다.

  콘솔에 보이는 것              원인                      고칠 곳
  ─────────────────────────────────────────────────────────────
  CORS 오류                     화면 주소를 API 가 모름    4단계 .env
  ERR_CONNECTION / 연결 실패    방화벽 또는 API 꺼짐       9단계 · 7단계
  엉뚱한 포트로 요청 중         화면 빌드의 포트가 다름    개발 PC 재빌드
  404                           역할이 뒤바뀜             5단계 xml 의 ROLE

  막히면 콘솔에 나온 글을 그대로 복사해서 물어보세요.


┌──────────────────────────────────────────────────────────────┐
│ 되돌리기 (원래 한 포트로)                                     │
└──────────────────────────────────────────────────────────────┘

  10분이면 돌아갑니다.

      cd C:\bizdash

      .\bizdash-api-service.exe stop
      .\bizdash-api-service.exe uninstall
      .\bizdash-web-service.exe stop
      .\bizdash-web-service.exe uninstall

      .\bizdash-service.exe install
      .\bizdash-service.exe start

  방화벽도 되돌립니다.

      Remove-NetFirewallRule -DisplayName "사업관리 대시보드" -ErrorAction SilentlyContinue
      New-NetFirewallRule -DisplayName "사업관리 대시보드" `
        -Direction Inbound -Protocol TCP -LocalPort 80 `
        -Action Allow -RemoteAddress 10.20.150.0/23

  .env 의 CORS_ORIGINS 는 비웁니다.

      CORS_ORIGINS=

  ※ 여기까지 하면 서버는 80 번으로 돌아오지만, 화면 파일은 아직 8081 을
    찾는 상태입니다. 개발 PC 에서 아래를 해야 완전히 원래대로 돌아갑니다.

      1. frontend/.env.production 의 VITE_API_PORT= 를 비운다
      2. powershell -ExecutionPolicy Bypass -File scripts\release.ps1
      3. git add -A  →  git commit  →  git push
      4. 서버에서 git pull 하고 서비스 재시작

  자료(데이터베이스)는 건드리지 않았으므로 그대로 있습니다.
  그래도 이상하면 1단계에서 받아 둔 백업으로 되돌립니다.
  방법은 docs/설치방법.txt 의 pg_restore 항목을 보세요.
