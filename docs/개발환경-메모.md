## 로컬 데이터베이스를 SQLite 로 둔 이유

계획에서는 `docker compose up` 한 줄로 PostgreSQL 까지 띄우려 했지만,
이 PC 에 Docker 가 없습니다. 관리자 권한 없이 PostgreSQL 을 띄우는 방법
(pip 로 설치되는 내장 PostgreSQL — `pgserver`, `postgresql-wheel`)도
Python 3.13 / macOS 용 배포본이 없어 설치되지 않았습니다.

그래서 이렇게 했습니다.

- `DATABASE_URL` 환경변수 하나로 로컬(SQLite)과 운영(PostgreSQL)을 오갑니다.
- PostgreSQL 전용 자료형(JSONB 등)은 쓰지 않고 SQLAlchemy 공통 자료형만 씁니다.
- SQLite 에서도 외래키 제약을 켜 둡니다. 안 그러면 PostgreSQL 에서만 나는 오류를
  로컬에서 못 잡습니다.

## 남아 있는 위험

**PostgreSQL 경로는 아직 한 번도 실행해 보지 못했습니다.** "로컬에서는 되는데
서버에서 안 되는" 상황이 생길 수 있습니다. 해소하는 방법은 셋 중 하나입니다.

1. 이 PC 에 Docker Desktop 을 설치한다 (설치에 관리자 비밀번호가 필요합니다)
2. 전산실에서 PostgreSQL 을 쓸 수 있는 서버를 받는다
3. 그때까지는 SQLite 로 개발을 계속하고, 서버가 생기는 즉시 마이그레이션을 돌려 확인한다

지금은 3번으로 진행 중입니다.

## 글꼴

프로토타입은 IBM Plex Sans KR 을 Google Fonts CDN 에서 받습니다.
병원 내부망에서 CDN 이 막히면 다른 글꼴로 떨어져 화면이 달라 보입니다.
글꼴 파일을 저장소에 포함시키는 작업은 **3단계(화면 이식)** 에서 함께 합니다.
그때 프로토타입과 나란히 놓고 비교하므로 차이를 바로 확인할 수 있습니다.

## 글꼴 — 해결됨 (3단계)

`scripts/fetch_fonts.py` 로 IBM Plex Sans KR 을 저장소 안에 담았습니다.
조각 376개 · 3.1MB 이지만, 한글은 유니코드 구간별로 나뉘어 있어 브라우저는
실제로 쓰는 조각만 받습니다. 사용자가 내려받는 양은 늘지 않습니다.

확인 결과: 화면을 띄웠을 때 **바깥으로 나가는 요청이 0건**이고,
본문 크기 16.8px·굵기 4종(400/500/600/700)이 모두 적용됩니다.

## SSL 인증서

macOS 에 python.org 파이썬을 설치하면 시스템 인증서를 못 찾아
`[SSL: CERTIFICATE_VERIFY_FAILED]` 가 납니다. 글꼴을 받을 때 실제로 났고,
**6단계 공고 수집에서도 똑같이 막힐 문제**라 미리 해결했습니다.

`backend/app/core/http.py` 의 `ssl_context()` 를 쓰면 certifi 인증서를 씁니다.
바깥에 요청하는 코드는 모두 이 함수를 쓰세요. 운영 서버(리눅스/도커)에서는
시스템 인증서가 정상이라 어느 쪽이든 동작합니다.
